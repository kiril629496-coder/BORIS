# Риск: add_account создаёт ложную задолженность у платных мультиаккаунтных клиентов

Статус: зафиксирован 31.07.2026. До запуска первого клиента НЕ исправляем.

## Суть
`POST /api/accounts/add_account` создаёт аккаунт с `billing_mode="auto"` и при `charge > 0`
пишет в Storage запись `billing` = `{"upgrade_due": <сумма>}` на новый аккаунт.
`billing.has_unpaid_upgrade()` затем отдаёт аккаунт как `active: False`,
`blocked_reason: "unpaid_upgrade"`.

Для клиента, которого ведут вручную и который уже оплатил пакет целиком, это ложный долг и
блокировка работающего аккаунта. Освобождение `OWNER_MANUAL_USER_ID = 2` не помогает: у
клиента собственный `owner_user_id`.

Замер 31.07: добавление второго аккаунта тестовому клиенту дало `доплата: 7000, оплачено: false`.

## Обход, действующий сейчас
Подключать аккаунты через `POST /api/inbox/slots/connect` — он создаёт
`Account(..., billing_mode="manual")` и долга не пишет.

## Правило до исправления
Из интерфейса запуска клиента путь к `add_account` не вести.

## Что решать потом
Либо не начислять `upgrade_due` при ручном биллинге, либо спрашивать режим при создании,
либо вести подключение аккаунтов только через слоты и убрать второй путь.
