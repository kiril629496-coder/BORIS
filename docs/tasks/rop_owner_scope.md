# Общий пакет РОП для нескольких аккаунтов одного владельца

Статус: не начата. Создана 31.07.2026. Запускать ПОСЛЕ запуска первого платного клиента.

## Текущая проблема
Пакет РОП (20 000 ₽ / 30 дней: 1500 минут, 450 разборов переписок, 30 отчётов по звонкам,
30 по перепискам) привязан к одному `account_id`. Клиенту с двумя аккаунтами Avito продаётся
ОДИН пакет, но технически его приходится начислять на каждый аккаунт отдельно — возникают
два независимых лимита, суммарный объём вдвое больше проданного, а в отчётности это выглядит
как две продажи.

## Затронутые функции (app/api/calltracking.py)
- `get_rop_minutes(account_id)` — стр. 942
- `_rop_period(account_id)` — стр. 1103
- `add_rop_package(account_id, minutes, chats, rep_calls, rep_chats, days)` — стр. 1151
- `get_rop_chats(account_id)`, `consume_rop_report(account_id, kind)`

## Текущие ключи хранения
Все в Storage `key="billing"` под конкретным `account_id`:
`rop_period_start`, `rop_paid_until`, `rop_reports_purchased_calls`,
`rop_reports_purchased_chats`, `rop_reports_used_calls`, `rop_reports_used_chats`,
`rop_overflow_minutes`. Израсходованные минуты считаются как SUM(minutes) по `call_analysis`
с фильтром `created_at >= rop_period_start`.

## Предлагаемое решение — owner-level key
Ввести `_rop_owner_key(account_id)` по образцу `_billing_owner_key` (billing.py:51-63):
возвращает `user:<owner_user_id>`, если у владельца больше одного аккаунта, иначе сам
`account_id`. Все перечисленные функции читают и пишут через неё. Расчёт израсходованного
меняется на выборку по ВСЕМ аккаунтам владельца.

## Миграция существующих данных
Для владельцев с одним аккаунтом — ничего не делать, ключ совпадает. Для владельцев с
несколькими: перенести ключи `rop_*` с аккаунта, где лежит активный пакет, на `user:<id>`;
при нескольких активных пакетах суммировать купленное и взять самый поздний `rop_paid_until`.
Скрипт с холостым прогоном и отчётом до/после.

## Обратная совместимость
Одиночные аккаунты должны работать без единого изменения в поведении. Проверяется тем, что
для них ключ не меняется.

## Тесты
- одиночный аккаунт: покупка пакета, расход, исчерпание — поведение не изменилось
- два аккаунта одного владельца: пакет куплен один раз, виден с обоих
- одновременное списание: звонок на первом и на втором аккаунте уменьшают ОБЩИЙ остаток
- отчёты сохраняют разбивку по аккаунтам
- истечение периода гасит пакет сразу на обоих
- владелец платформы (is_own) сохраняет безлимит
