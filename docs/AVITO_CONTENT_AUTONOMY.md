# BORIS — автономный контентный модуль Avito

Версия правил: `avito-content-autonomy-v1`.

## Один владелец процесса

Контент не создаёт второй Feed Factory и не публикует объявления отдельным скриптом.
Единственный production-контур: `campaign_prepare` → текущий Feed Factory → canonical validation → canonical XML projection → существующий lifecycle загрузки/публикации.

## Приоритет источников фактов

1. Поля текущей карточки и подтверждённый intake категории.
2. Подтверждённый профиль клиента и описание компании.
3. Собственные существующие объявления этого же Avito-аккаунта.
4. Загруженные клиентом тексты/файлы и референсы, если они помечены как источник.
5. Сохранённый анализ конкурентов — только как источник структуры/болей, но не чужих фактов.
6. Модель не имеет права придумывать цены, сроки, гарантии, наличие, доставку, опыт, кейсы, характеристики или результат.

Данные другого аккаунта никогда не используются.

## Тексты

Автоматический режим по умолчанию — local-first, без LLM/API.
BORIS использует детерминированный фактический копирайтер и затем существующие бесплатные нормализаторы Feed Factory.

Правила:
- заголовок не длиннее 50 символов;
- описание: целевой диапазон 1200–2000 символов;
- жёстко допустимый диапазон текущего quality-gate: минимум 650, максимум 2400 символов;
- обычный текст Avito, без HTML, Markdown и спинтакса;
- первый блок называет услугу/направление и географию;
- минимум 4 смысловых блока;
- CTA обязателен;
- цена из модели никогда не становится канонической ценой карточки;
- при цене «от» сохраняется семантика «от»;
- запрещённые клиентом заявления удаляются локально;
- внизу создаётся отдельный предметный пример/сценарий;
- уникальность должна быть смысловой и детерминированной, а не искусственным хвостом для обхода дублей;
- полные дубли описаний не проходят validation.

Локальная Ollama-модель не обязательна. Она может быть только дополнительным rewrite-слоем, если ответила вовремя и её результат прошёл те же проверки фактов и качества. Таймаут локальной модели не блокирует кампанию.

## Файлы и импорт

Поддерживаемый безопасный импорт фактуры не означает автоматическую верификацию фактов.
Извлечённый текст сначала считается источником, а не истиной.
Существующие объявления импортируются через штатный `import_existing`, а не через второй storage-путь.
Обязательные поля Avito берутся из текущего template/category contract и direction intake.
`template_id` и `category_path` не подменяют друг друга.

## Фото

Порядок:
1. фото, загруженные клиентом в конкретную кампанию;
2. уже approved media этого же аккаунта;
3. stock/owner-media подбор штатным `auto_media`;
4. платная генерация картинки — только резерв.

Для zero-touch подготовки требуется ровно 3 проверенных фото карточки, не считая баннера.
Фото другого аккаунта запрещены.
Отклонённое фото запоминается для конкретного semantic fingerprint и не покупается/проверяется бесконечно повторно.
Поворот, зеркалирование и подмена товара ради «уникальности» запрещены.

## Баннер

По умолчанию баннер строится бесплатно:
- реальное owner/approved фото остаётся визуальным источником;
- BORIS локально делает квадратный banner через Pillow;
- видимый текст берётся только из проверенного заголовка;
- максимум 4 первых смысловых слова заголовка, не более 2 строк;
- минимальный размер шрифта 58;
- фотография остаётся главным объектом, текст — в нижней зоне;
- никакой AI-кириллицы, выдуманных цен, телефонов, логотипов или новых обещаний.

Если нет проверенного фото, карточка возвращается к media stage.
Она не имеет права молча купить AI-картинку при нулевом резервном бюджете.

## Платные вызовы

По умолчанию платный fallback выключен.

Сейчас production-режим намеренно жёстче: платный fallback выключен полностью.
Даже если задать `BORIS_CONTENT_PAID_FALLBACK=1`, положительный лимит на карточку и суточный лимит, BORIS только зафиксирует, что платный резерв запрошен, но не выполнит вызов. Причина: эти два новых числа пока не связаны единым жёстким cross-provider ledger, а декоративный «лимит» недопустим.

Текущий статус: `paid_limit_adapter=disabled_until_cross_provider_hard_cap_exists`.

Отдельный автоматический платный анализ конкурентов также выключен.

Существующие BORIS `ai_budget`/provider guards, idempotency key и single-paid-attempt остаются защитой старых явно запущенных платных операций, но автономный контентный worker на них не переходит.

Когда будет внедрён единый enforcing-adapter, платный резерв можно будет включить только после доказательства двух реальных потолков: на одну карточку и на сутки/аккаунт. Повтор одного экономического intent не должен создавать второе списание.

## XML и автозагрузка

Контентный модуль не пишет свой XML-формат.
Используется только canonical Feed Factory delivery projection.
Перед готовностью обязательны:
- account scope совпадает;
- title/description заполнены;
- обязательные category/template params заполнены;
- media graph совпадает с payload;
- semantic/media validation зелёный;
- нет duplicate descriptions;
- canonical identity валидна;
- official XML check проходит.

Подготовка XML не равна публикации.
Загрузка/публикация выполняется только существующим BORIS lifecycle и его publication lock.
После передачи Avito тексты/фото/баннеры кампании не мутируются до завершения publication state.

## Идемпотентность и повторы

- `campaign_prepare` — единственный zero-touch worker.
- Job replay должен продолжать с checkpoint, а не создавать вторую кампанию.
- Платные intent всегда имеют стабильный ключ.
- Существующий баннер/кэш/проверенный asset переиспользуется.
- Ошибка provider/QA не запускает скрытый бесконечный платный цикл.
- При недостатке фактуры/фото модуль fail-closed и оставляет карточку draft/retry без выдумки.

## Разрешённые автоматические действия

BORIS может без участия владельца:
- собрать local-first текст из подтверждённой фактуры;
- нормализовать структуру и CTA;
- подобрать/reuse media в рамках того же аккаунта;
- собрать баннер локально;
- выполнить validation;
- подготовить canonical XML;
- повторить безопасный idempotent job.

BORIS не может без отдельного разрешённого бюджета:
- покупать текстовую генерацию;
- покупать image generation/edit;
- автоматически покупать competitor analysis;
- превращать retry в новое списание.

## Инвариант

Если бесплатный путь не может доказать корректность результата, BORIS останавливает конкретную карточку или возвращает её на предыдущий этап. Он не выдумывает факт и не включает платный API сам.
